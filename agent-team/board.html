Team Board

Each column is a GDF phase or gate; each row is a member of your team. Click a column header for what that stage asks of you, a lane name for the role's primer and the facts it needs about your game, or a cell to see and edit what the role does, expects, delivers, and recommends there. The example game is Signal Station from the GDF reader.

How to read this board. It is a sample for the GDF reader's example game, Signal Station.
  1. Columns run left to right through the project: each phase of work, then the gate that decides whether it continues. Gate columns are tinted.
  2. The first row holds the key questions. At every gate you answer the same four (Opportunity, Execution, Risks and mitigations, Alignment), worded for that gate, plus the gate's own. Phase columns list what that work must answer before the gate.
  3. The next two rows are people. You decide; the instructor approves gates. The eight rows below are your agent team. Agents recommend.
  4. Each cell says what that member does at that point, what they receive (← from whom), what they hand on (→ to whom), and what they recommend or decide.

Click a column header or a role name for more. Underlined abbreviations show their meaning on click.

When you open this page with python -m team serve (an address starting with http://127.0.0.1 or http://localhost), the page shows your role files as of the last render, and Save updates the lanes, slots, and game of the role file in agent-team/roles/ after the checks pass; the rest of the file (permissions, subtitle, and the Instructions) stays as you wrote it. When you open the file directly, edits are saved in this browser until render writes a changed version of this page; to keep them, open a lane, choose Show role file, and replace the game, slots, and lanes blocks in agent-team/roles/<id>.md with the ones it shows. A role marked revised in your repository's coverage map changed after a handoff showed a weakness; that needs Git history, so this page shows default and tailored only.
